## Resumo executivo (stakeholder não-técnico)

O time realizou uma revisão completa do sistema nesta sprint. Na parte do chatbot WhatsApp, foram corrigidos dois problemas críticos: o bot havia gerado um erro silencioso em produção ao tentar interpretar uma resposta mal formatada da IA — isso agora é recuperado automaticamente. Também foram fechadas brechas onde o bot poderia prometer agendamentos diretamente ao cliente (contra a regra de usar o AppBarber), expandindo a proteção de 1 em 5 cenários para 5 em 5.

No painel de atendentes, o dashboard recebeu melhorias de usabilidade: o snooze de conversas agora usa um seletor visual com atalhos de tempo (1 hora, 4 horas, 24 horas, 1 semana) em vez de caixas de texto básicas. A linha do tempo das conversas agora mostra quem assumiu e quando. O painel também mostra a contagem de clientes aguardando no título da aba do browser, permitindo monitoramento sem olhar para a tela.

Um gap operacional foi resolvido: antes, reativar um atendente desativado exigia acesso direto ao banco de dados. Agora existe uma função administrativa para isso no próprio sistema.

## Riscos mapeados

| Risco | Severidade | Mitigação |
|---|---|---|
| Zero testes automatizados (TD-002) | Alto | 8 camadas de lógica sem cobertura — qualquer refatoração é risco cego |
| Datetime naive no MySQL (TD-001) | Médio | Configurar `TZ=UTC` no ambiente de produção mitiga; sem isso, `BOT_REATIVAR_APOS_HORAS` pode calcular errado |
| JSON truncado por max_tokens não detectado | Médio | `finish_reason=length` não é verificado; resposta incompleta vai para parser e pode falhar |
| Mobile responsiveness zerada (BUG-3 regressão) | Médio | Redesign removeu todos os `@media` breakpoints; atendentes em celular não conseguem usar o dashboard |
| SSE drop-oldest sem notificação ao cliente | Baixo | Fila de 100 eventos; sob carga extrema eventos são descartados silenciosamente |
